### 1. Naming and Formatting Conventions

Use these guidelines to maintain consistent naming, file structures, and code layout across the codebase.

---

#### 1. File and Header Conventions
*   **File Names:** Match the class name exactly (e.g., `HttpsServer.hpp`, `HttpsServer.cpp`). Use `.hpp` for C++ headers and `.cpp` for implementation.
*   **Header Guards:** 
    *   Use `#pragma once` for modern C++ and PAL/application components.
    *   Use traditional `#ifndef FILE_NAME_H` guards only for pure C-compatible HAL interface files (e.g., `ihal.h`).
*   **Includes Grouping:** Group includes logically with single empty lines:
    1. Matching Header (for `.cpp`)
    2. Local Application Headers
    3. Third-party/SDK Headers (e.g., `<esp_https_server.h>`)
    4. C++ Standard Library (e.g., `<vector>`)

---

#### 2. Naming Conventions

| Entity                 | Casing Style            | Rules & Examples                                                                                                                                          |
| :--------------------- | :---------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Interfaces**         | PascalCase / `I`-Prefix | Start with `I`. (e.g., `IHttpServer`, `IHttpUri`). Pure abstract HAL classes may use screaming snake-case after the prefix (e.g., `IHAL_IO`, `IHAL_MEM`). |
| **Concrete Classes**   | PascalCase              | Standard C++ classes (e.g., `HttpsServer`, `HttpUri`).                                                                                                    |
| **Public Methods**     | camelCase               | Must start with a lowercase letter (e.g., `init()`, `registerUri()`, `sendWsMessage()`).                                                                  |
| **Private Methods**    | camelCase / `_`-Prefix  | Start with a single underscore (e.g., `_populate_config()`, `_handle_event()`).                                                                           |
| **Private Members**    | camelCase / `_`-Prefix  | Prefix member variables with a single underscore (e.g., `_server`, `_sslConfig`, `_started`).                                                             |
| **Local Variables**    | camelCase               | Use camelCase (e.g., `maxClients`, `platformUri`). Exception: Match SDK types when mapping raw hardware descriptors (e.g., `clientId_sockfd`).            |
| **Parameters**         | camelCase               | Use camelCase (e.g., `options`, `payload`). Avoid Hungarian notation.                                                                                     |
| **Macros / Constants** | SCREAMING_SNAKE         | Capitalized words separated by underscores (e.g., `HAL_INITIALIZED`, `ENABLE_SYS_LOG_D`).                                                                 |

---

#### 3. Formatting and Structure Rules

*   **Brace Placement:** Use Allman style (braces on a new line) for namespace blocks, classes, functions, structure definitions, and `switch` blocks:
    ```cpp
    class HttpsServer
    {
    public:
        sys_error_t start()
        {
            // ...
        }
    };
    ```
*   **File-Scope Helpers:** Encapsulate local file-scope helpers or converters in anonymous namespaces within the `.cpp` file:
    ```cpp
    namespace
    {
    httpd_ws_type_t toPlatformWsType(WsFrameType type)
    {
        // ...
    }
    } // namespace
    ```
*   **Indentation:** Use 4 spaces per indentation level. Do not use raw tabs.

---

#### 4. Multi-Line Macro Invocation Formatting
When calling logging/error macros (`RETURN_IF_ERROR`, `RETURN_ON_ERROR`) that span multiple lines, each parameter must be placed on its own line and documented with trailing, right-aligned comments:

```cpp
RETURN_IF_ERROR(
    (length < min_header_size),                                                                                                 // Expression
    ERROR_INVALID_ARG,                                                                                                          // Error code
    SYS_LOG_E("First write chunk size too small for header validation: %zu bytes (min required: %zu)", length, min_header_size) // Error message
);
