### Recommended Code Convention Markdown Files

| File Name                                       | Purpose / Core Subject                                                     | Key Contents Tailored to Your Codebase                                                                                                                                                                                                                                                                                                                       |
| :---------------------------------------------- | :------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`1. Naming and Formatting Conventions.md`**   | Rules for code appearance, identifiers, and file structure.                | Case style (camelCase vs. snake_case), prefixes (e.g., `_` for private members), brace placement, line-length limits, tab vs. space settings, and source/header file extension policies (`.cpp`/`.hpp`).                                                                                                                                                     |
| **`2. Error Handling and Recovery.md`**         | Standardization of status codes and execution control.                     | Correct usage of `sys_error_t`, standard macro invocation patterns (`RETURN_IF_ERROR`, `RETURN_ON_ERROR`), error translation architectures (mapping SDK-level `esp_err_t` to application-level codes), and criteria for calling `abort()` vs. returning gracefully.                                                                                          |
| **`3. Resource Management and RAII.md`**        | Preventing memory leaks, dangling pointers, and hardware state corruption. | Rule of Five implementation rules (deleting copy/move constructors for hardware-wrapping HAL classes like `HttpsClient` or `mem_ota`), heap allocation restrictions (avoiding dynamic allocation in ISRs or tasks), alignment-safety rules (using `std::memcpy` instead of pointer casts for arbitrary raw buffers to avoid strict-aliasing and bus errors). |
| **`4. Logging and Diagnostics.md`**             | Unified guidelines for console output and system telemetry.                | Proper mapping of log levels (`SYS_LOG_E`, `SYS_LOG_W`, `SYS_LOG_I`, `SYS_LOG_D`), strict control over compile-time log stripping (using `#define ENABLE_SYS_LOG_D` only in local modules), format specifier requirements (like `PRIu32`), and rules preventing performance-heavy logging inside high-frequency loops or ISRs.                               |
| **`5. Header and Include Layout.md`**           | Guidelines for compile-time optimization and clean API exposure.           | Include order hierarchy (Local headers $\rightarrow$ System/HAL headers $\rightarrow$ ESP-IDF SDK headers $\rightarrow$ C++ Standard Library headers), strict enforcement of `#pragma once`, appropriate use of forward declarations to reduce compile-time dependencies, and prevention of `using namespace` in header files.                               |
| **`6. Concurrency and ESP-IDF Integration.md`** | Thread-safety and RTOS interaction standards.                              | FreeRTOS task safety, rules for sharing class resources via Mutexes/Semaphores, restrictions on what functions can be called from an Interrupt Service Routine (ISR) context, and thread-safe driver access guidelines.                                                                                                                                      |
| **`7. API Level Doxygen Guide.md`**             | Standardization of public interfaces (complements the In-Body Guide).      | Templates for file-level headers (e.g., copyright blocks, author metadata, date), class declarations, and public method descriptions utilizing `@brief`, `@param[in/out]`, `@return`, and `@note` tags.                                                                                                                                                      |
