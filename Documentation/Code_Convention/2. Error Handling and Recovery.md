### Error Handling and Recovery

Use this standard to handle, log, and recover from errors using the system's custom macros and the `sys_error_t` status type.

---

#### 1. Core Error Types
*   **System Status Type:** All functions representing operations that can fail must return a `sys_error_t` code (where success is `ERROR_SUCCESS`).
*   **SDK Error Translation:** When invoking ESP-IDF or other third-party APIs, translate the SDK-level error (e.g., `esp_err_t`) to `sys_error_t` using `TRANSLATE_ERROR(err)` before bubbling it up.

---

#### 2. Error Handling Macros Reference

| Macro                                                         | Expression Evaluated (`expr`)         | Behavior on Error / Failure                                                                 | Recommended Use Case                                                    |
| :------------------------------------------------------------ | :------------------------------------ | :------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------- |
| **`RETURN_ON_ERROR(expr, ...)`**                              | Evaluates a `sys_error_t` expression. | Executes cleanup arguments (`...`) and returns the evaluated error.                         | Calling internal operations that return `sys_error_t`.                  |
| **`RETURN_ON_ERROR_WITH_LOG(expr, message, ...)`**            | Evaluates a `sys_error_t` expression. | Logs file/line, error code, and `message`. Executes cleanup (`...`) and returns the error.  | Logging failures from internal operations while bubbling up the error.  |
| **`ON_ERROR_WITH_LOG(expr, message)`**                        | Evaluates a `sys_error_t` expression. | Logs file/line, error code, and `message`. Does **not** return.                             | Non-fatal steps where execution must continue even if the step fails.   |
| **`RETURN_IF_ERROR(expr, errorCode, ...)`**                   | Evaluates a boolean condition.        | If `true`, executes cleanup (`...`) and returns `errorCode`.                                | State checks (e.g., `ptr == nullptr`) or checking raw SDK return codes. |
| **`RETURN_IF_ERROR_WITH_LOG(expr, errorCode, message, ...)`** | Evaluates a boolean condition.        | If `true`, logs file/line and `message`, executes cleanup (`...`), and returns `errorCode`. | Validations that require explicit error logging and context.            |
| **`BREAK_ON_ERROR(expr)`**                                    | Evaluates a boolean condition.        | If `true`, exits the containing loop.                                                       | Serial/batch operations or processing loops.                            |

---

#### 3. Execution Control & Cleanup Patterns

*   **Handling State Cleanup via Variadic Arguments (`...`):**
    The macros accept trailing arguments (`__VA_ARGS__`) specifically to perform inline cleanup (resetting states, freeing buffers, unlocking mutexes) prior to returning.
    ```cpp
    RETURN_ON_ERROR(
        _prepare_request(method, path, headers, body, body_len),    // Expression
        SYS_LOG_E("Failed to prepare request!");                    // Log Message
        _active_response_buf = nullptr;                             // Cleanup
    );
    ```
*   **Evaluating Return Codes Safely:**
    Always cast the output of an evaluated expression inside the standard return macros if the expression type is not implicitly `sys_error_t`.

---

#### 4. Template Code Patterns

##### Pattern A: Validating Prerequisites (Boolean Conditions with Right-Aligned Comments)
```cpp
sys_error_t mem_ota::validateIncomingImageHeader(const uint8_t* data, size_t length)
{
    constexpr size_t min_header_size = sizeof(esp_image_header_t) + sizeof(esp_image_segment_header_t) + sizeof(esp_app_desc_t);
    
    RETURN_IF_ERROR(
        (length < min_header_size),                                                                                                 // Expression
        ERROR_INVALID_ARG,                                                                                                          // Error code
        SYS_LOG_E("First write chunk size too small for header validation: %zu bytes (min required: %zu)", length, min_header_size) // Error message
    );
    // ...
}
```
